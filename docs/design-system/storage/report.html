Storage mockups report

Fable's report on the storage mockups of 2026-11-14: three options for each of three parts, and what it recommends. Open the mockups.

Things to know first

  • Project names are examples (example-app 56 folders 38 GB, example-shop 69 folders 24 GB, mulebox 19 folders 1.3 GB); the sizes are the real node's. One idle project, example-docs (0.7 GB, 16 days), is made up, so totals read 145 folders and 64.0 GB.
  • Docker split is a reading: job images (3.1 GB) and the build cache (9.7 GB) counted as mulebox's, the other 6.7 GB of images as not mulebox's and left alone. Say if the build cache should count otherwise.
  • Made up: the cleanup time "tonight at 03:00", the Mac node's numbers, and "Not now asks again in 7 days". The real sweep runs hourly.
  • Checked at 1440 px in headless Chrome only; in Edge at 544 px the index, the Storage view and the settings, with no sideways scroll. The notices page was not opened in Edge.

Storage view

A
A Storage page, by project. A fifth page in the header. The disk as one ruler: what mulebox takes by kind, what is not mulebox's, free space, the reserve hatched at the end. A line for the next cleanup with Show and Clean now, then projects that open to their branch folders, caches, runners, Docker and logs. Each row: size, last job, what happens to it, copy path, keep, clean. Room for 145 folders and a second node; the longest list.
B
On the Machines page, by what goes next. Each node gets Jobs and Storage tabs; folders grouped by fate, soonest first: tonight, 1 to 3 days, 4 to 7 days, kept as latest, kept by you. Project size is a column, not a row; the Machines page gets long.
C
A window from the Disk panel, by size. One new line in the Disk panel opens a window for the shown node: the ruler and one list, biggest first. Least to build, fastest answer when space is short; tight for 145 folders, one node at a time.

In all three, Clean first lists what goes, what stays and the free space after; nothing is removed before the red button.

Storage settings, in the node's settings window

A
A Storage tab in the same grammar. Each of the four settings a panel with Suggested, Yours and Runs with, as slots has. Nothing new to learn; twelve rows for four numbers.
B
One Storage panel. No tabs, a line per setting under Dev mode; the suggestion speaks up only when yours differs. Compact, but a second way to show a setting in one window.
C
The rules as a sentence, tried on the disk. The controls inside one sentence; the ruler moves the reserve as you set it and says what your values would do, before you save. Furthest from the existing rows, most to build.

Notices

The example: build-1 a few days on, 44 GB free, 5 GB under its 49 GB reserve.

A
In the strip under the header. The out-of-step strip carries both: the warning in amber with Review what goes, the suggestion as a grey line with Clean it, Keep it, Not now. Cannot be missed; a 0.7 GB suggestion sits above the CPU panel on every page.
B
Where the thing is. The warning on the node's row in the Machines box, the suggestion on the project's row in the Storage view. Quietest; a suggestion can go unseen for weeks.
C
A "To decide" list in the header. A mark with a count opens a short list with each item's answers; the red strip only when jobs could fail for lack of room. Scales to many idle projects; a new header part and two warning levels.
D
The review window, shared by all three. A checklist, cheapest loss first, with just enough ticked to get back above the reserve; kept folders listed but not offered.

Fable's recommendation

Storage view: A, entered by C's one-line link in the Disk panel; B's "going tonight" group as the list behind "Show".

Settings: A, as it matches the Suggested, Yours, Runs with rows you picked for this window, plus C's line of what your values would do.

Notices: B for the idle suggestion, A for the reserve warning, which needs a decision.

Follow-up noted, not changed

With a long reading such as "118.7 GB of 234.4 GB", the Memory panel's header grows to three lines. Fix idea: shorten the caption to "5 min" when it does not fit beside the reading, with the full caption in its title; or drop the caption at that width.
