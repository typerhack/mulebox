Storage mockups

Mockups of 2026-11-14, to pick from before anything is built. A node keeps a reserve of free space, removes branch folders unused for 7 days, keeps each project's latest folder, suggests cleaning a project idle for 14 days, and asks before it removes anything else. Three things to decide: where the owner sees what mulebox takes, how the rules are set, and where mulebox speaks up.

Picked by the user on 2026-11-14 and built in 1.25.0: Storage view A, with C's line in the Disk panel and B's "going next" list behind a button; settings A, with C's one line of what the values would do; notices A for the low-space warning and B for the idle-project suggestion, with the review window. What was built follows the node's real report, so it differs from these pages where they guessed: there is no "tonight at 03:00" (a node sweeps hourly), and Docker is shown but never cleaned.

Static pages with example data: build-1 is a Linux node with a 490 GB disk, 410 GB used, of which mulebox takes 85.6 GB; build-mac is a Mac node. Project names are examples. The theme switch is on every page; nothing is saved. Colours, type, space, corners and motion come from tokens.css through the shared mockup stylesheet. New parts, to be added to design-system.md with what is picked: the disk ruler with its hatched reserve, the keep mark, and the list a clean shows first.
